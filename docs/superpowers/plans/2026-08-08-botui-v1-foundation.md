# BotUI V1 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a working, language-agnostic BotUI V1 foundation that validates a screen DSL, renders regular Telegram messages, auto-lays out semantic buttons, generates page/cursor pagination controls, compiles Telegram payloads, and exposes the same renderer through a small HTTP adapter.

**Architecture:** TypeScript is only the implementation language; `BotUI DSL v1` and `RenderPlan` are the stable public contracts. Core packages remain stateless and Telegram-token-free. Stateful pagination metadata is represented in context/action tokens, while storage is left behind an interface for later adapters.

**Tech Stack:** Node.js 24 LTS, TypeScript 5.x, Vitest, Zod, Fastify, pnpm workspaces.

## Global Constraints

- Target Telegram Bot API 10.2 semantics without binding the DSL to a specific framework.
- Core must not require a Bot Token, Redis, MySQL, or any external service.
- Button styles are semantic: `primary | success | danger | default`; no HEX/RGB button promise.
- `callback_data` generated by the library must stay within 64 UTF-8 bytes.
- Regular text renderer uses Telegram HTML and escapes user data.
- Pagination is a V1 first-class feature: page, cursor, keyboard/content/detail-capable primitives.
- Default render flow is deterministic and testable from `Screen + Data + Theme + Locale + Context -> RenderPlan`.
- No production code is added before the corresponding failing test is written and observed.
